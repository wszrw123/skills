# 图片驱动的 UI 设计与操作减负

目标：图片建立质感和辨识度，交互减少用户需要思考、填写和点击的事项。视觉丰富与操作简单分别设计、一起验收。

## 先确定当前任务的边界

- 结合现有页面、用户截图、代码和反馈定位要改的流程；明确哪些区域已经满意，优先保留并延伸其设计语言。
- 用户只要分析时交付建议；已经要求实施时直接完成授权范围的可回滚改动，不追加设计批准或执行方式选择。
- 这是视觉与交互方法，不规定技术栈、全站重构、子代理、worktree 或部署。根据真实改动范围使用必要的领域技能和验证。
- 默认关注手机体验，但用户明确的设备、品牌、设计稿和任务范围优先。不把手账、奶油色、番茄红或贴纸指定为所有产品的固定风格。

## 1. 提取可延伸的视觉语言

从用户满意的页面或参考中提取：主辅色、材质、图像类型、光影、图标笔触、字体层级、构图与留白。用简短说明指导实现，无需为局部修改另写长篇设计文档。

先完善一条高频任务涉及的页面和控件，再延伸同一套语言。避免首页精致、表单和详情仍是另一套模板。

图片不必铺满每个区域：让主视觉吸引注意，让内容区保持阅读节奏，用小尺寸素材完成品牌呼应。装饰密度应服务产品定位。

## 2. 按职责选择图片素材

| 视觉职责 | 优先选择 | 实现要求 |
| --- | --- | --- |
| 氛围、封面、场景 | 摄影或生成的场景图 | 给文字留安静区域，检查手机裁切和明暗对比 |
| 用户内容 | 用户实际照片 | 不用示意图冒充用户记录，支持加载失败和预览 |
| 核心入口、分类 | 成套透明插画、SVG/PNG | 统一配色、光影、比例与笔触，实看小尺寸辨识度 |
| 返回、关闭、状态等细符号 | 清晰的 SVG 图标 | 保留熟悉语义，触控区域大于可见图形 |
| 材质、装饰 | 少量纹理、纸张、边饰等素材 | 不遮挡文字、焦点或可点击区域 |

优先复用适合的现有素材。需要生成或编辑位图时使用可用的 imagegen 工具并遵循其技能；需要外部素材时确认可复用来源和必要署名。没有生图能力时使用现有资产或合适的 SVG，并说明限制，不伪称已生成。

成套生成提示词应明确：共同风格与配色、每个物件的功能、透明背景、单格留白、光照方向，以及不含文字和水印。图集还应指定行列、顺序和每个格子的尺寸一致。生成后实际检查透明通道、边缘、图格位置和目标尺寸效果；如背景或物件错误，通过图像工具修正。

保留原始素材，按实际显示尺寸提供优化格式；复用图片组件、图集坐标或图标映射，避免每个页面单独拼样式。不要将按钮文字、表单和动态数据烘焙进图片；图片内部的小物件位置不应成为点击命中的唯一依据。

## 3. 让视觉形象解释功能

使用符合产品语境的物件表达动作，同时保留简短文字。例如生活手账可用铅笔表达记录、相纸表达相册、书签表达收藏、纸章表达完成；这些是示例，其他产品应选择自己的语汇。

- 主操作采用最清楚的视觉层级，不能只靠装饰让用户猜按钮用途。
- 功能标签已经清楚、整行也可点击时，可移除多余箭头；返回、展开等必要方向和状态仍应明确。
- 统一默认、按下、禁用、加载、成功和失败状态。装饰图片不能取代状态反馈或无障碍名称。
- 微动效适量，支持减少动态效果；高频操作不等待装饰动画结束。

## 4. 先减少输入，再整理入口

对当前高频任务逐项判断信息和动作的必要性：

| 类型 | 默认处理 |
| --- | --- |
| 完成任务必须且无法可靠推导的信息 | 保留为首屏主要输入 |
| 可可靠带入的信息，如当前时间 | 自动填写，并提供修改入口 |
| 可稍后补充的信息 | 设为选填，按需展开 |
| 用户已有的内容或常用组合 | 支持选择、复用或一步完成 |
| 修改、备注等低频动作 | 放入清楚可发现的次级入口 |

不能为了减少控件隐藏核心操作，不能悄悄改变用户选择的日期、数量或目标。默认值遵守现有业务规则；未知数值不直接等同于真实的零，遇到旧接口限制应明确展示语义并保留兼容性。

低成本且可恢复的动作适合“一步执行 + 成功反馈 + 撤销”；重要删除等按风险保留确认。保存中防止重复提交，失败保留草稿并允许重试。

如果使用识别或自动预填，先确认该能力属于用户授权范围，处理等待、失败和手动修正；异步结果不覆盖用户已经编辑的内容。减少人工操作不等于擅自增加付费调用、上传或数据采集。

## 5. 同时验收外观和操作成本

按改动范围检查，不默认全仓测试或全站改造：

- **视觉一致性：** 用户满意区域是否保留；主视觉、图标、按钮、表单是否属于同一套语言；图片失败时内容仍可理解。
- **操作成本：** 对比关键任务前后必填项、默认可见控件、点击步骤；不要只统计控件变少，还要确认操作容易发现。
- **手机可用性：** 典型触控目标至少约 44 CSS px，Web 输入字号通常至少 16px；检查窄屏裁切、键盘遮挡、弹窗、底部安全区、焦点和横向滚动。按项目平台规范调整。
- **业务闭环：** 实测本轮相关保存、修改、取消、撤销、失败重试及刷新持久化；检查时间格式、步长、长度和后端约束。测试使用隔离数据，复用合适的已有浏览器会话与工具。
- **交付质量：** 运行与修改相称的类型检查、测试或构建，实际查看截图；关注图像体积和首屏加载。未实测的设备或服务明确标注。

最终说明哪些视觉改变、哪些操作减少、验证证据和真实限制。先交付可体验结果，避免只有概念说明或生图展示而没有完成用户要求的实现。
